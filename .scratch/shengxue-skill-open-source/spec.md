# shengxue-skill 全国实时检索开源版设计规格

状态：已批准  
目标版本：v0.1.0 公开预览版  
目标仓库：`sarry12227/shengxue-skill`（独立公开仓库）  
设计日期：2026-08-22

## 1. 背景

现有 `shengxue-skill` 已具备分数换位次、校排名折算、普通批冲稳保、多元路径推荐、Markdown/DOCX 输出等确定性能力，也积累了湖北、黑龙江、上海三类真实试跑经验。

当前版本仍不适合直接公开：实时检索主要依靠 Agent 临时编写抓取、OCR 和转换脚本，无法保证不同 Agent 与运行环境的结果一致；真实数据存在来源、授权、字段和质量问题；部分跨省、3+3、DOCX、安全与文档行为和规格不一致。

本次改造将项目升级为“Agent 实时检索与理解 + 本地确定性证据管线 + 可追溯计算与报告”的独立开源 Skill。

## 2. 已批准的设计决策

1. 只公开 `shengxue-skill`，不公开完整的 `shengxue-ai-planner` 或机构内部系统。
2. 采用混合架构：Agent 负责检索、网页理解和必要的视觉识别；Skill 负责证据记录、去重、标准化、校验、计算、报告和合规门禁。
3. 默认实时查询用户所在省份的高考、学校喜报、多元升学和专项政策数据，不依赖内置真实喜报完成全国覆盖。
4. 检索每类信息时考察搜索结果中的前 10 个候选，并按独立发布者、引用链和内容指纹去重。
5. 官方来源不足时，允许多自媒体交叉验证后作为“参考级数据”参与计算，但必须满足本规格的证据门槛并显式标注。
6. 不同环境必须先做能力探测；能力不足时明确降级，不能假装完成全国实时查询。
7. 公开仓库默认只携带虚构测试数据。真实数据若要随版本发布，必须单独完成来源、授权、许可证和时效审查。
8. 第一版以 `v0.1.0` 公开预览版发布，不宣称生产可用或提供录取承诺。

## 3. 目标与非目标

### 3.1 目标

- 在具备联网能力的兼容 Agent 中，为全国新高考省份用户生成实时、可追溯的多元升学方案。
- 让相同输入、相同证据包在不同 Agent 和操作系统上得到一致的确定性计算结果。
- 让报告中的每个关键数字都能反查其来源、提取方法、检索日期和验证状态。
- 对官方网页、附件、二维码、图片表格、权威转载和自媒体整理形成统一的证据处理流程。
- 保持 Skill 形态：复制或克隆仓库即可使用，不要求部署中央服务。
- 为贡献者提供清晰的数据结构、验证工具、测试和省份规则扩展方式。

### 3.2 非目标

- 不建设中央数据 API、Web 服务、用户账号、学生档案或运营后台。
- 不恢复机构产品匹配、价格、销售钩子、引流/正价双模式或品牌资产。
- 不保证所有网站都可访问，也不绕过登录墙、验证码、反爬或付费墙。
- 不把缺失、冲突、屏蔽或无法验证的数据强行补成精确数值。
- 不以免责声明替代数据质量、隐私或安全控制。

## 4. 总体架构

系统分为六层：

1. **Agent 编排层**：识别用户意图、逐步提问、生成检索计划、调用宿主提供的搜索/浏览/视觉能力并解释最终报告。
2. **环境能力层**：探测联网、网页读取、文件下载、XLSX/PDF 解析、图片 OCR、Python 版本和可选依赖。
3. **证据层**：记录候选来源、发布主体、发布日期、URL、检索日期、内容摘要、提取方式、内容哈希、可信级别和采纳状态。
4. **标准化与验证层**：把检索结果转换为版本化结构，执行字段、年份、科目组、院校代码、单调性、重复行、覆盖范围和异常波动校验。
5. **确定性计算层**：执行分数换位次、喜报推断、普通批冲稳保、选科过滤、多元路径和专项适配。计算层不访问网络。
6. **报告与合规层**：生成 Markdown，按需生成 DOCX，展示证据状态、来源、覆盖范围、冲突与免责声明，并执行隐私、营销、敏感信息和来源完整性扫描。

Agent 不能直接把网页数字写入正式推荐。任何数字必须先进入证据包，通过门禁后才能进入计算层。

## 5. 环境能力与兼容性

### 5.1 能力档位

- **完整档**：具备联网搜索、网页读取、文件下载、XLSX/PDF 解析和图片 OCR，可执行全国实时完整流程。
- **标准档**：具备联网和文本/结构化附件处理，但无可靠 OCR；跳过仅以图片发布的表格，并明确报告缺失范围。
- **离线档**：只使用用户提供或本地已有的数据包；不得宣称完成实时全国查询。

### 5.2 能力探测

每次新会话在实质检索前运行预检。预检输出机器可读结果和面向用户的简要说明。宿主 Agent 工具名不写死，统一按“搜索、打开网页、下载、视觉识别”能力契约描述；Codex、Kimi、Claude 等环境的具体适配说明放在参考层。

Python 最低版本为 3.10。核心计算保持轻依赖；XLSX、PDF、DOCX 和 OCR 适配器通过明确的可选依赖组提供。缺少依赖时必须在预检阶段发现，不能到报告生成末尾才失败。

## 6. 用户旅程

1. 询问省份，识别 3+1+2、3+3 或传统高考模式，并检索当年该省政策；当年尚未发布时按规则回退。
2. 询问首选与再选科目。3+3 省份采集完整选科组合，不套用物理/历史结构。
3. 询问年级、学校全称、最近考试分数与年级排名；若用户有省排名或高考分数则优先采用。
4. 为校排名路径检索学校喜报并形成推断证据；无可靠喜报时给出降级路径，不伪造省排名。
5. 询问意向院校、地区、专业、港澳意愿、路径偏好、奖项和活动经历；不询问“当下最该做什么”，由系统给出建议。
6. 分别检索一分一段、投档线、招生计划、选科要求、强基、综评、港澳和命中的专项/特殊路径政策。
7. 形成证据包，完成标准化、校验和可信度判定。
8. 调用确定性计算引擎，生成普通批与多元路径结果。
9. 生成 Markdown 报告并完成合规扫描；按用户要求再生成 DOCX。
10. Agent 在对话中按“成绩定位、普通批、多元路径、行动建议”四部分完整解读，不新增报告外的数据。

## 7. 检索任务与独立性判定

### 7.1 分任务检索

下列任务必须分别检索，不能用一次宽泛搜索替代：

- 省份政策与考试模式；
- 一分一段表；
- 普通批/提前批/综评批等投档数据；
- 学校喜报与高中出口；
- 院校招生专业和选科要求；
- 强基计划专业、入围/录取、培养与转段；
- 综合评价条件、成绩比例、校测和出口；
- 港澳招生方式、英语要求、费用和出口；
- 推荐结果中出现的每类专项、定向、预科、民族班、中外合作和地方计划。

### 7.2 前 10 候选

每类查询最多考察搜索结果中的前 10 个可访问候选。候选数量不足时记录实际数量，不通过重复查询制造虚假独立性。

### 7.3 独立发布者去重

以下任一情形成立时，多条结果只算一个来源：

- 同一发布机构或同一站点的不同 URL；
- 标题、正文和表格高度相同，明显为同稿转载；
- 多个页面共同引用同一个上游整理稿，且无独立复核；
- 同一账号在不同平台同步发布相同内容。

证据包记录内容指纹和引用链，用于解释为什么某条候选未计入独立来源数量。

## 8. 信源等级与交叉验证

### 8.1 三级信源

- **A 级原始来源**：教育考试院、教育部门、高校招生网、学校官网、学校官方公众号及其他能确认发布主体的原始渠道。
- **B 级权威整理**：教育类权威媒体、专业升学平台、明确转载官方材料的可靠页面。
- **C 级独立整理**：自媒体、论坛、个人或机构整理内容。

媒介形式不决定级别；学校官方公众号属于原始来源，自媒体平台上的个人账号仍为 C 级。

### 8.2 采纳规则

- A 级来源可直接形成“官方级证据”，但仍需通过结构和一致性校验。
- 无 A 级时，B 级来源必须说明上游出处，并尽量通过官方锚点或第二个独立来源复核。
- 只有 C 级时，至少需要 3 个独立发布者对关键数字一致，且通过内部一致性、跨年度异常和上下游数据校验，才可形成“多源参考级证据”。
- 搜索前 10 个候选不足 3 个独立来源时，不满足 C 级计算门槛。
- 离散事实和精确数字发生冲突时不取平均、不凭经验选边。无法排除冲突的证据标为“冲突”，不得进入确定性推荐。
- 适合用范围表达的推断结果可输出区间，但必须展示各来源、推断方法和不确定性。

### 8.3 证据状态

每个关键字段具有以下状态之一：

- `official`：原始来源确认；
- `corroborated`：多个独立来源一致；
- `reference`：达到多源参考门槛但非官方；
- `inferred`：由已采纳证据按公开方法推断；
- `conflict`：来源冲突，未进入计算；
- `missing`：未找到可用证据；
- `masked`：官方仅给边界或屏蔽值；
- `partial`：数据只覆盖部分页面、院校或分数区间。

## 9. 证据包

每次运行生成独立证据包，至少包含：

- 会话随机标识，不含学生姓名或联系方式；
- 查询任务、关键词和查询时间；
- 原始 URL、规范化 URL、发布主体和来源级别；
- 发布日期、适用年份、省份、批次和科目组；
- 提取方法：HTML、附件解析、二维码、OCR、人工结构化或转载；
- 内容/附件哈希、文件大小、媒体类型和页数；
- 提取出的事实及其字段级来源；
- 独立性判定、交叉验证结果、异常和采纳/拒绝原因；
- 标准化数据文件与校验报告；
- 计算参数和引擎版本。

默认只在本地临时工作目录保留。原始网页或附件不提交到 Git；长期保留时仅保存有必要的结构化事实、引用和哈希，遵守原始内容的版权条件。

## 10. 标准化与数据契约

所有输入先转换为版本化 Schema。省份配置定义：

- 高考模式、科目组或选科组合；
- 志愿单位；
- 批次、专业组和院校代码语义；
- 分数与位次范围；
- 冲稳保参数及其依据；
- 多元路径适配规则；
- 官方入口与省份特殊发布方式；
- 屏蔽值、断档组和缺失值处理规则。

字段命名统一使用通用省份语义，移除 `is_inside_hubei` 等湖北专属名称。备注字段统一为 `remarks`。校验器从省份配置读取合法科目组，不再写死物理/历史。

标准化门禁包括：必填字段、数据类型、年份、科目组、院校/专业组代码、唯一键、分数与位次范围、分数—累计位次单调性、重复转载行、页数完整性、覆盖范围和跨年度异常。

## 11. 图片、OCR、二维码和屏蔽值

- 二维码仅作为公开附件的发现方式；上传到第三方解码服务前确认内容不含个人信息，并在证据包标记第三方处理。
- OCR 结果必须检查总页数或声明实际覆盖页数，至少复核两个分布在不同位置的锚点，并执行单调性和行数检查。
- 局部 OCR 或区间采样只能形成 `partial` 证据，报告必须声明覆盖范围。
- “580 分以上”“前 100 名”“由学校逐一告知”等边界或屏蔽数据为 `masked`，不得把边界值当作精确投档线参与排序；可在报告中单列说明。
- 断档组、分数为 0、空值和标题行必须显式计数并从计算数据中剔除。

## 12. 计算规则

### 12.1 分数与省排名

优先使用用户提供的省排名，其次使用经验证的一分一段表反查。表格为 `partial` 时，只有输入位于已验证覆盖范围内才允许计算。

### 12.2 校排名与喜报推断

喜报推断使用人数法、线差法和用户实际考试数据交叉校验。学校规模、分数段人数和对应一分一段数据均须有字段级证据。

结果必须为三档或区间，状态为 `inferred`，并展示年份、来源、方法、容差和主要冲突。无法形成足够锚点时停止校排名折算，建议改用分数、省排名、市排名或联考排名。

不得把未经授权的内置真实喜报作为全国实时流程的默认依据。

### 12.3 普通批冲稳保

冲稳保由标准化投档数据和省份配置驱动。选科要求在推荐前过滤。数据只覆盖部分院校时，空档只能表述为“当前已验证覆盖范围内未找到”，不能表述为“没有符合院校”。

院校层次、所在省市和特殊类型必须来自数据或证据，缺失时不参与对应排序条件。目标城市不能只透传，若设计声明其影响推荐，则必须有明确、可测的排序规则。

### 12.4 多元升学路径

强基、综评、港澳及其他路径不能全国统一套用无依据的固定修正值。等效位次修正、分档阈值和候选规则必须由省份/路径配置给出依据；无依据时展示历史区间与资格匹配，不生成伪精确冲稳保。

强基介绍采用“国家高精尖、关键核心技术和紧缺领域人才培养，包含基础学科与工科强基”的当前口径。逐校检索招生专业、培养方案和转段方向。

专项、定向、中外合作、民族班和预科等特殊路径必须逐类检索并解释报考条件、与普通路径区别、就业/地域限制、服务期、违约后果及费用补助。关键约束未核实时只能列为“待核实路径”，不得正式推荐。

## 13. 报告与解读

Markdown 是正式默认产物，DOCX 为可选产物。报告至少包含：

1. 成绩定位、判断方法、数据依据和不确定性；
2. 普通批冲 3、稳 4、保 5，或如实说明经验证覆盖范围内的空档；
3. 多元路径的学校、专业、政策、培养、转段、出口和关键限制；
4. 按优先级给出的当下行动建议；
5. 证据清单、数据覆盖、冲突、缺失、检索日期和免责声明。

关键数字附近展示证据编号和状态，不只在文末堆积 URL。脚本数据、在线补全和推断内容分区呈现。

“AI 生成，仅供参考”在开头、关键章节和结尾出现，但不能用来掩盖来源冲突或计算缺陷。

## 14. 失败与降级

- 网络或宿主搜索不可用：进入离线档，使用用户提供/本地数据，或停止全国实时流程。
- 当年数据未发布：回退上一年；一分一段和投档数据最多回退两年，喜报最多考察近三年，超出窗口只能作为低权重背景证据。
- 官方数据不足：执行 B/C 级交叉验证；未达到门槛则标记缺失。
- OCR 能力缺失：不处理图片表格，寻找其他可验证格式或声明缺失。
- 数据冲突：不取平均，不参与精确推荐；适合时输出范围。
- 数据覆盖不完整：声明覆盖范围，不把抓取缺失当成真实空档。
- 专项政策关键约束缺失：降级为待核实路径。
- 报告或 DOCX 合规扫描失败：删除未通过产物并说明命中项。
- 外部请求只做有限次数重试，失败后停止或降级，不无限循环。

## 15. 隐私与安全

- 学生姓名、电话、身份证、住址等不是运行所需字段，不进入证据包、缓存或日志。
- 报告默认使用匿名标题；用户主动要求姓名时，仅写入本地最终报告，不写入中间文件。
- 工作目录、缓存、输出和本地环境文件默认加入 Git 忽略。
- 下载器仅允许 HTTP/HTTPS，阻止 localhost、回环、链路本地和内网地址，限制重定向、文件大小、超时和允许的媒体类型。
- 下载目标必须位于明确工作目录内，阻止绝对路径覆盖和路径穿越。
- 不执行下载内容，不解析宏，不绕过验证码、登录墙或反爬。
- 第三方二维码/OCR 服务的使用必须在能力说明和证据包中披露。
- 发布前扫描密钥、手机号、身份证、真实学生姓名、报告产物、品牌、价格与销售内容。

## 16. 独立仓库结构

公开仓库包含：

- `SKILL.md`：精简的宿主无关编排协议；
- `README.md`：项目简介、安装、能力档位、示例、限制和免责声明；
- `pyproject.toml`：Python 版本、命令入口和可选依赖；
- `scripts/`：预检、证据、标准化、验证、计算、报告和合规脚本；
- `schemas/`：证据、标准化数据、校验报告和会话清单结构；
- `references/`：检索、信源、省份和宿主适配手册；
- `fixtures/`：纯虚构或获得明确再分发许可的测试数据；
- `tests/`：单元、契约、回放、安全和端到端测试；
- `.github/`：CI、Issue/PR 模板、依赖更新和安全说明。

不进入用户运行路径或公开版的内容：机构数据库导出脚本、依赖私有 `shengxue-system` 的 parity 脚本、未经确认的数据、真实报告和品牌模板。

## 17. 测试与质量门禁

### 17.1 自动测试

- 算法测试：分数换位次、锚点推断、边界分档、选科过滤、3+3、屏蔽值、异常输入和路径参数。
- 证据测试：来源去重、引用链、三源一致、冲突拒绝、字段级证据和覆盖状态。
- Schema 契约测试：版本兼容、通用字段和动态科目组。
- 固定回放测试：用脱敏、裁剪和可再分发样例覆盖黑龙江二维码、上海图片 OCR、喜报冲突、断档、多代码与特殊备注。
- 报告测试：数字可追溯、空档措辞、来源状态、隐私和合规。
- DOCX 测试：CI 安装可选依赖后完整运行，不允许全部跳过。
- 安全测试：SSRF、内网地址、异常重定向、超大文件、路径穿越和恶意媒体类型。

### 17.2 CI 与定时烟测

主 CI 覆盖 Windows、Linux、macOS 和 Python 3.10–3.13，使用固定样例，不依赖实时网站。

定时联网烟测检查主要官方入口和适配器是否失效。烟测失败创建维护告警，但不因第三方网站临时波动破坏主分支确定性测试。

### 17.3 发布门禁

发布前必须通过：全部测试、Schema 校验、来源完整性、文档链接、许可证、敏感信息扫描、Skill 结构检查、示例报告合规扫描和跨平台安装验证。

## 18. 许可证与数据边界

代码采用 MIT 许可证。代码许可证不自动覆盖抓取或随包数据。

公开仓库默认只提供虚构测试数据、来源目录和抓取/导入工具。任何真实数据快照必须提供独立的数据来源与许可声明；不能确认再分发权利时，只保存 URL、结构化事实和哈希，或由用户运行时自行检索。

## 19. GitHub 开源发布

发布流程包括：

1. 将 `shengxue-skill` 初始化为独立 Git 仓库；
2. 完成 README、贡献指南、许可证、行为准则、安全政策、变更记录和维护说明；
3. 配置 CI、Issue/PR 模板、依赖更新和敏感信息门禁；
4. 整理仓库简介、Topics、首个 Release 说明和路线图；
5. 创建公开仓库 `sarry12227/shengxue-skill`；
6. 推送经过发布门禁的历史；
7. 发布 `v0.1.0` 公开预览版；
8. 在 README 显著说明能力档位、支持边界、数据来源规则和免责声明。

建议仓库简介：

> 面向全国新高考省份的开源 AI 升学规划 Skill：实时检索并交叉验证公开数据，通过本地确定性管线生成可追溯的普通批冲稳保与多元升学方案。

## 20. 现有问题的迁移要求

本次实现至少修复以下已确认问题：

1. README 的“零网络”描述与实时检索流程冲突；
2. 跨省临时数据目录在完整报告中因写死省份映射而失败；
3. 校验器写死物理/历史，无法正确支持 3+3；
4. `remark`/`remarks` 字段与唯一键不一致；
5. `is_inside_hubei` 等字段不是全国通用语义；
6. DOCX CLI 未贯通再选科目；
7. DOCX 测试在常用环境中全部跳过；
8. 真实 `schools.csv` 混入大学且缺少高中层级，真实代理降级不可用；
9. 51 行喜报中绝大多数没有足够锚点，文档夸大了实际可用性；
10. 喜报数据授权未确认；
11. 多元路径固定减 4000 位次缺少全国适用依据，顶尖位次还可能产生非正等效位次；
12. 完整报告对可选路径数据缺失处理不一致；
13. 合规扫描只覆盖部分价格模式，不能代表完整隐私与发布扫描；
14. 二维码下载脚本缺少 SSRF、文件大小和目标路径安全限制；
15. 私有系统导出和 parity 工具不适合作为独立公开 Skill 的运行依赖；
16. 实时检索、OCR 和临时数据转换缺少可复现证据包与自动测试；
17. 局部采样或屏蔽值可能被误当成完整精确数据；
18. 当前仓库缺少稳定的 Python 包元数据、跨平台 CI 和完整 GitHub 社区文件。

## 21. 验收条件

- AC1：完整档环境中，给定任一新高考省份，流程能产出能力报告、检索计划、证据包、校验报告和最终 Markdown，或明确说明无法完成的步骤。
- AC2：相同输入和相同证据包在 Windows、Linux、macOS 上得到相同的确定性计算结果。
- AC3：只有 C 级来源时，少于 3 个独立来源或关键数字冲突的事实不得进入精确计算。
- AC4：搜索结果重复转载不会增加独立来源数量。
- AC5：3+1+2 与 3+3 的科目结构和校验均由省份配置驱动。
- AC6：屏蔽值、局部 OCR 和区间采样不会作为完整精确数据进入推荐。
- AC7：喜报推断展示三档/区间、来源、方法、容差和证据状态；无可靠锚点时停止折算。
- AC8：普通批推荐先完成选科过滤，并如实区分“真实空档”与“已验证覆盖范围内未找到”。
- AC9：多元路径参数没有依据时不生成伪精确冲稳保；专项关键限制未核实时不正式推荐。
- AC10：报告中所有关键数字可反查字段级证据，冲突、缺失和参考级数据清晰可见。
- AC11：DOCX 功能在 CI 中安装依赖后完整测试，再选科目与 Markdown 行为一致。
- AC12：下载工具通过 SSRF、内网地址、重定向、大小限制和路径安全测试。
- AC13：公开仓库不包含真实学生报告、机构品牌销售内容、密钥或未确认授权的数据。
- AC14：独立仓库可从干净环境安装，运行预检和固定样例端到端流程。
- AC15：GitHub 仓库具备简介、README、许可证、贡献指南、安全政策、行为准则、CI、Issue/PR 模板和 `v0.1.0` Release。
