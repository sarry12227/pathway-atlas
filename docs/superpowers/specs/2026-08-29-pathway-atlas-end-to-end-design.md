# 多元星途端到端规划闭环设计

**日期：** 2026-08-29

**状态：** 已通过会话级方案确认，等待书面规范复核

**范围：** Skill 编排、实时检索交接、画像决策、多元路径排序、普通批代表院校、行动计划与验收

## 1. 背景

当前项目已经具备画像、查询计划、证据采纳、数据验证、位次定位、普通批推荐、多元路径评估和 Markdown/DOCX 报告组件，但组件之间仍依赖宿主 Agent 临时组织文件和调用顺序。现有合成测试能够证明组件契约，不能证明普通家长从自然语言问询开始即可稳定获得完整规划。

本设计把一次咨询变成可恢复、可验证的单一规划会话。宿主 Agent 负责使用当次可用的 search、browse、vision 和本地工具执行公开资料检索；Python 负责状态、契约、证据、计算和报告。项目不预装动态录取数据库，也不让 Agent 凭记忆补造数据。

用户提供的专业规划样例仅用于提炼通用字段和决策顺序。学生身份、机构品牌、收费项目、服务套餐、营销话术、个案结论和未经重新验证的数字不得进入公开仓库、测试或输出模板。

## 2. 产品承诺

一次成功会话必须直接回答三个问题：

1. 学生当前大致处于什么位次情景；普通批可重点查看哪些冲、稳、保和观察院校。
2. 哪些多元升学路径应主攻、重点准备、备选、观察或不建议，为什么。
3. 当前最需要做什么，先后顺序、时间窗口、完成标准和不做的代价是什么。

结论必须来自当次可重放的公开数据和版本化决策规则。第三方资料达到既有信源门槛后可以参与判断，但必须标注 `corroborated` 或 `reference`；单源第三方只能作为发现线索或观察理由。

## 3. 不可变边界

### 3.1 README 首段

README 开头必须逐字保留以下内容，位于标题、Logo、徽章和项目介绍之前。测试以 UTF-8 字节和代码块内容双重锁定；任何后续任务不得改写、扩写或移动这段文字。

````markdown
一句话让AI调用此skill：

```bash
请使用你当前环境的 Skill 安装能力，从 GitHub `https://github.com/sarry12227/pathway-atlas` 安装 `pathway-atlas`（多元星途）；如果 GitHub 无法访问，请改用 Gitee 镜像 `https://gitee.com/sarry1/pathway-atlas`。若环境没有专用安装工具，请将仓库克隆或下载到当前 Agent 的 Skills 目录，确认根目录存在 `SKILL.md` 且其中 `name` 为 `pathway-atlas`，然后重新加载并调用它。
```
````

### 3.2 数据与隐私

- 不收集学生姓名、电话、身份证、详细住址、通信 ID、凭证或本地绝对路径。
- 不把真实省份的动态分数、位次、投档线和政策快照随代码包发布。
- 真实数据由宿主 Agent 在用户会话当时检索，保存到会话私有临时目录，并通过现有安全下载、适配器、EvidenceStore 和 validator。
- 未经用户明确授权，不上传、发布、提交或推送会话材料和报告。
- 规划样例原件不进入 Git，脱敏不等于取得第三方数据再分发授权。

## 4. 推荐架构

采用“统一状态机 + 宿主工具适配”架构。只修改提示词会继续依赖 Agent 临场发挥；为每个宿主复制一套业务实现又会产生规则漂移。统一状态机保存唯一语义，Codex、Claude Code、Kimi 和 generic host 指南只映射工具能力。

### 4.1 规划会话

新增 factory-only、不可变的 `PlanningSession` 与公开 CLI `scripts/planning_session.py`。会话阶段固定为：

```text
intake
  -> profile_confirmed
  -> preflight_complete
  -> query_plan_ready
  -> research_in_progress
  -> evidence_finalized
  -> calculation_complete
  -> report_published
```

每次转换必须验证前置状态并生成新的 canonical session snapshot。状态文件只存在于会话私有工作目录，使用随机机器 ID，不包含学生身份或原始自由文本。失败后可以从最后一个已验证 snapshot 恢复，不重复询问已经确认的问题。

公开命令提供以下最小能力：

- `init`：把 Agent 内部整理的匿名问卷答案转换为 `PlanningProfile`，返回已知、未知和待确认摘要。
- `confirm`：锁定画像 digest；之后若用户修改答案，显式创建新画像版本并使下游结果失效。
- `next`：输出下一批可执行 `QueryTask` 或本地 gate，不暴露内部路径。
- `ingest`：接收 adapter/bridge 产生的结构化结果和 provenance，不接受自然语言数字。
- `finalize`：最终化并重放验证 evidence 与 dataset。
- `compute`：调用共享位次、院校、路径和报告模型。
- `status`：输出阶段、覆盖、缺口和下一步，不输出敏感值。

Skill 的职责是循环调用 `next`，使用宿主真实工具完成返回任务，再调用 `ingest`。用户不创建 JSON、不选择脚本、不理解内部目录。

### 4.2 查询与检索

初始查询计划只依赖已确认画像和受信省份目录，不再要求事先存在含动态策略的 `province.json`。稳定配置与动态数据拆分：

- `ProvinceDiscovery`：省份名称、别名、考试模式、官方发现根；随包维护。
- `ProvinceCalculationPolicy`：普通批分层参数和方法版本；来自版本化决策规则，不伪装成官方政策。
- `ProvinceResearchSnapshot`：当次检索得到的一分一段、投档、招生计划、选科要求和路径政策；只存在于会话证据中。

每类数据独立按 `Y -> Y-1 -> Y-2 -> Y-3` 查询，优先最近可比年份。任务必须声明：

- 目标事实、年份、省份、canonical subject key 和结构化 target；
- 官方发现根和建议查询词；
- 必须提取的字段、允许的媒体类型和 adapter；
- candidate cap、网络重试上限、停止条件和 unavailable reason；
- 接纳所需的来源等级、独立发布者数量与冲突行为；
- 对普通批、位次渠道或路径政策的唯一 bridge。

宿主不得以搜索摘要直接形成事实。候选必须打开原页或附件；无法访问原文时只能保存发现线索。A 源可形成 `official`；无 A 时两个独立 B 完全一致可形成 `corroborated`，三个独立 C 完全一致可形成 `reference`。冲突不平均、不挑选方便值。

查询分两层执行：

1. **核心定位层：** 省份模式、一分一段、普通批投档、招生计划和选科要求。核心层达到最低覆盖后即可先形成普通批答案。
2. **画像相关路径层：** 根据资格、兴趣、年级、准备资产和限制只查询相关路径；明确不适用的路径保留排除理由，不进行无边界全量检索。

### 4.3 证据到运行时对象的交接

所有公开材料必须经过结构化 bridge，禁止测试式手工拼 `EvidenceFact.value`：

- 普通批：保留现有 `admission_bridge`，从 exact adapter row、QueryTask、ValidatedAdmissionRow 和 coverage 生成整行绑定。
- 位次渠道：新增 rank evidence bridge，从一分一段、联考、校级喜报锚点和可解释 cohort 数据生成 `rank_channel:*` 或 anchor。
- 多元路径：新增 pathway extraction/bridge，把 HTML、PDF、OCR 的字段级结果转换为严格 `PathwayPolicyProjection`，再生成 `pathway_policy:*`；缺少任何关键字段时只产生 partial/missing，不由 Agent 补写。
- 省份研究：新增 research snapshot builder，按查询任务和年份将已认证 score/admission/policy facts 组成 validator 可读取的数据集，不让 Agent创建任意 `province.json`。

所有 bridge 必须保留 source IDs、year、method、locator、coverage、warnings 和 row/projection hash。

## 5. 完整画像模型

保留不超过 20 题的对话体验，但把第 20 题的矩阵和现有自由文本拆成机器可判定字段。画像由以下六组构成：

1. **学业上下文：** 省份、城市、学校、年级、班型、选科、原始分/赋分口径、预计高考年份。
2. **成绩定位：** 多次考试的日期、范围、分数、满分、校排/联考排位、参考人数、最高和常态表现、波动性。
3. **兴趣与目标：** 目标院校、专业、地区及理由，毕业方向，学校/专业优先级。
4. **准备资产：** 学科优势、竞赛、科创、研究性学习、研学/夏校、英语、表达面试、体测和其他可核实经历。
5. **资格与硬约束：** 专项资格、户籍/学籍类别、选科、身体/政审/体能、预算、民办/合作办学接受度、服务期、定向就业、地域、调剂和风险偏好。
6. **问题与期望：** 当前焦虑、最想解决的问题、期望交付物。

字段使用必须可审计。每个画像字段都要在以下三种状态之一：

- `decision_input`：影响位次、院校、路径或行动排序；
- `display_only`：仅为报告解释，必须说明为何不参与计算；
- `not_applicable`：当前会话不适用并记录原因。

不允许收集后静默丢弃。`PlanningProfile.to_decision_trace()` 输出字段到规则的映射，测试要求全部字段被覆盖。

## 6. 决策模型

### 6.1 位次与普通批

位次继续输出乐观、中性和保守情景。优先级为：

1. 当年官方分数和一分一段；
2. 最近三年可比官方一分一段；
3. 有来源的联考或校级锚点；
4. 经过覆盖和来源门禁的第三方 cohort 参考。

每个情景披露年份、方法、边界、置信度和来源。普通批按版本化 `ProvinceCalculationPolicy` 生成冲、稳、保、观察代表院校，并结合目标专业、城市、院校、排除地区、调剂和风险偏好排序。不能把院校最低投档线当作热门专业录取线；专业证据不足时明确要求逐校核专业组和专业数据。

### 6.2 多元路径

每条路径先过硬门禁，再做序贯排序：

1. `eligibility`：资格和排除条件；
2. `academic_fit`：位次、选科、学科优势和招生要求；
3. `interest_fit`：专业方向、长期计划和地区偏好；
4. `readiness`：已有材料、经历、考试、面试或体测准备；
5. `urgency`：报名或准备窗口是否临近；
6. `burden`：费用、服务期、地域、准备时间和机会成本；
7. `strategic_value`：对目标院校/专业的增益和普通批替代价值；
8. `evidence_quality`：政策年份、来源等级和字段覆盖。

输出决定仍为“主攻、重点准备、备选、观察、不建议”，资格状态仍为“已满足、部分满足、暂未满足、待核验、不适用”。决定必须携带 reason codes，不能仅因来源是 official 就自动主攻，也不能仅因历史回退就自动重点准备。

规则保存在版本化 `decision-policy` 中。规则包含依据、适用范围、版本、复核日期和测试场景；不得声称为官方政策。专业规划样例贡献的通用方法只以规则和字段形式公开，不保留来源身份、商业术语或个案数字。

## 7. 行动计划

新增不可变 `ActionItem`：

- `action_id`、标题和完成标准；
- `phase`：现在、本学期、下一阶段、报名前、出分后；
- `deadline` 或受控时间窗口；
- `urgency`、`strategic_value`、`effort`；
- `blocking`、依赖 action IDs；
- 对应学校、专业或 pathway IDs；
- 个性化理由、缺口、证据状态和 source IDs；
- 未执行后果与复核条件。

排序为确定性序贯规则，不把不同维度粗暴相加：

1. 已知硬截止且窗口最短；
2. 阻断其他任务或资格判断；
3. 高战略价值且准备周期长；
4. 能快速消除关键不确定性；
5. 其余按阶段、投入和稳定 ID 排序。

行动来自三处：画像缺口、路径政策的 timeline/preparation、普通批证据与专业组复核。相同动作去重后合并来源和目标。报告首先列出 3–7 项“当前最需要做的事”，再给完整分阶段时间表；不能只有通用免责声明。

## 8. 错误与降级

- 宿主没有联网能力：只消费已认证本地材料，报告明确 offline；不伪造当前结论。
- 当前年未发布：逐年回查，最多三年；历史数据标明基线和不可比风险。
- 只有第三方：达到门槛后形成带标签判断；未达到门槛时可给方向性观察和“下一步找什么”，不输出伪精确数字。
- 普通批核心数据可用、路径政策不足：先完成普通批，路径逐项 unavailable；反之亦然。
- 任一 stage 失败：保存受控 reason code 和缺口，不输出绝对路径、原始异常或个人信息。
- 画像修改：使依赖旧 digest 的查询、证据、计算和报告失效，必须重放受影响阶段。

## 9. 输出结构

Markdown 和 DOCX 继续共享同一 `ReportModel`，顺序调整为：

1. 结论摘要与免责声明；
2. 当前最需要做的 3–7 项；
3. 位次情景与置信度；
4. 普通批冲稳保和代表院校；
5. 多元路径决策矩阵；
6. 每条重点路径的机会、挑战、个人匹配、差距和准备动作；
7. 分阶段行动时间表；
8. 证据、年份、覆盖和不确定性。

报告不承诺录取，不复制商业服务项目，不推荐付费测评、培训或咨询。需要专业探索时输出可由学生自主完成的公开活动和信息收集任务。

## 10. 兼容与迁移

- 保留现有 validated dataset/evidence/report API，先由新 session 调用，避免一次性重写计算内核。
- `query_plan` 新增画像/目录入口；旧显式 ProvinceConfig 入口仅作为内部兼容路径，完成迁移后删除，不恢复 legacy 固定位次或默认阈值。
- `PlanningProfile` 使用 schema 新版本；旧 v2 只通过显式迁移器转换，并为新增字段写入 `unknown`，不猜测答案。
- host guides 和 SKILL.md 只描述统一状态机，不复制决策阈值或来源门槛。

## 11. 测试与验收

### 11.1 组件与契约

- README 首段字节级不可变测试。
- 会话阶段、恢复、画像修改失效和 path-neutral 错误测试。
- 查询计划对 `Y..Y-3`、A/B/C、停止条件和画像相关路径裁剪的 mutation canaries。
- adapter -> bridge -> EvidenceStore -> validator 的真实对象测试；禁止手工成型事实绕过。
- 所有画像字段 decision trace 覆盖测试。
- 同分数但奖项、兴趣、预算、地域、服务期或风险偏好不同，路径、院校排序或行动必须出现可解释差异。
- 行动排序的截止、阻断、长期价值、快速消歧和稳定排序测试。
- 商业内容、学生身份和样例原文不得出现在 tracked source、fixture、snapshot 或报告。

### 11.2 端到端黑盒

使用 fake host tool 构造真实调用形状，从自然语言问卷答案开始，不允许测试直接创建 profile、province、evidence 或 pathway facts。至少覆盖：

- 有官方当年数据的普通批和多元路径；
- 当年缺失、回查历史三年的情景；
- 两个 B 或三个 C 形成带标签参考；
- 校排经学校/联考锚点形成位次区间；
- 一条主攻、一条备选、一条不建议及差异化行动；
- 3+1+2 和 3+3；
- offline 和部分能力降级。

### 11.3 真实 Agent 验收

发布前必须从干净安装分别在至少一个 generic/Codex 类宿主和一个 Kimi/Claude 类宿主完成真实会话：

1. 用户只提供自然语言首问和问卷答案；
2. Agent 不要求用户制作 JSON 或提供本地路径；
3. Agent 实际检索并打开来源，不把搜索摘要当证据；
4. 生成同时包含代表院校、路径决定和优先行动的报告；
5. 人工抽查所有数值和政策能回到来源；
6. 对两个不同画像得到合理且可解释的差异。

真实 Agent 验收未通过前不继续对外分发或宣传为完整方案生成器。

## 12. 实施顺序

4. 补齐 rank/pathway/research bridges。

6. 引入版本化多元路径决策和 ActionItem 排序。
7. 迁移共享报告模型与 Markdown/DOCX。
8. 跑全量、clean install、隐私与确定性门禁。
9. 完成真实 Agent 验收；验收通过后再请求用户授权同步 GitHub、Gitee 和第三方目录。

## 13. 完成定义

只有同时满足以下条件才可宣称本设计完成：

- 普通用户不接触内部 JSON、文件路径或脚本选择；
- 动态数据全部来自当次可重放检索，而不是预装或 Agent 记忆；
- 20 题字段全部有可审计用途；
- 位次、院校、路径和行动共享同一画像与证据 snapshot；
- 报告能明确下判断，也能解释证据等级和不确定性；
- 当前行动按时间和价值排序且具有完成标准；
- 参考方案中的个人与商业内容没有进入公开产物；
- README 固定首段未变化；
- 自动化与真实 Agent 端到端验收都通过；
- 发布仍需用户单独明确授权。
